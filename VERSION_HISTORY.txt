《前进四 / ADVANCE FOUR》版本更新记录

用途：
记录项目各版本的主要新增、调整与修复内容。

文档定位：
- README.txt：项目大方针、玩法定位与核心设计。
- WORKFLOW.txt：项目开发与协作的大方针。
- PROJECT_STRUCTURE.txt：项目框架与目录结构总纲。
- VERSION_HISTORY.txt：各版本实际更新内容记录。

记录原则：
1. 每次正式生成新版本时，在本文件顶部追加一条版本记录。
2. 只记录实际已经完成的修改，不记录尚未实现的计划。
3. 重点记录：新增功能、数据结构变化、目录调整、重要规则变化、Bug 修复。
4. 纯数值微调可合并描述，不必逐项记录。
5. 版本号与项目发布版本保持一致。


========================================
v0.18
========================================

新增：
- 新增 game/ship/projectile/ 目录。
- 新增 ProjectileRuntime。
- 新增 projectile_runtime.tscn。
- 新增 projectile/README.txt。
- RuntimeShip 新增 PROJECTILE_RUNTIME_SCENE。
- RuntimeShip 新增 projectile_spawned 信号。
- WeaponRuntime fired 后，RuntimeShip 现在会自动创建 ProjectileRuntime。
- ship_movement_test HUD 新增弹丸生成事件计数。

Projectile 行为：
- ProjectileRuntime.setup() 接收世界坐标发射点、世界坐标发射方向和 firepower。
- Projectile 使用 fired 时的 world_direction 作为固定飞行方向。
- Projectile 在 _physics_process() 中按 direction * speed * delta 进行世界空间直线飞行。
- Projectile 生命周期结束后自动 queue_free()。
- Projectile 保存 firepower，但当前不应用伤害。
- Projectile 视觉暂时使用简单白色图形。

当前 Prototype 参数：
- projectile speed = 700。
- projectile lifetime = 2.0 秒。

结构原则：
- WeaponRuntime 继续只负责选敌、瞄准和产生 fired 事件。
- RuntimeShip 负责把 fired 转换为 ProjectileRuntime 生成。
- ProjectileRuntime 作为 RuntimeShip 的同级节点加入世界，而不是作为飞船子节点，因此发射后不会继续跟随飞船自身的平移或旋转。
- 已发射 Projectile 拥有独立生命周期。
- Projectile 不修改 ShipData。
- firepower 继续来自 WeaponModuleDefinition / Excel 数据链。
- speed / lifetime 当前仍属于 ProjectileRuntime Prototype 参数，尚未写入 Excel 数据真源。
- 飞船模块仍允许分开放置，不要求相邻、连通或填满网格。

当前范围：
- 已完成 Projectile 生成。
- 已完成直线飞行。
- 已完成生命周期自动销毁。
- 尚未加入碰撞。
- 尚未加入命中检测。
- 尚未加入伤害。
- 尚未加入阵营过滤、穿透、爆炸、跟踪或弹丸继承飞船速度。

v0.17
========================================

新增：
- WeaponRuntime 新增自动目标选择。
- WeaponRuntime 新增可旋转炮塔瞄准。
- WeaponRuntime 新增自动开火冷却。
- RuntimeShip 新增 weapon_target_group，默认 enemy_targets。
- 新增 game/ship/dev/weapon_target_dummy.gd，用于自动炮塔测试。
- ship_movement_test 会自动创建 enemy_targets 测试目标。

调整：
- module.rotation_quarters 从“固定最终发射方向”调整为“炮塔初始朝向”。
- WeaponRuntime 在战斗中可以独立于 RuntimeShip 持续旋转。
- 每个 WeaponRuntime 独立搜索攻击范围内距离自身最近的目标。
- 当前目标失效、离开攻击范围或退出场景后会重新选敌。
- 炮塔按照 turn_speed_degrees 逐步转向目标，不瞬间锁定。
- 炮口与目标方向误差进入 fire_angle_tolerance_degrees 后视为瞄准完成。
- 有有效目标、瞄准完成且 fire_interval 冷却结束时自动触发 fired。
- PlayerShipController 移除 Space 手动齐射输入，恢复为只负责移动控制。
- RuntimeShip.request_fire() / WeaponRuntime.fire_once() 暂时保留为调试接口。
- PROJECT_STRUCTURE.txt 更新到 V0.17。
- game/ship/README.txt、runtime/README.txt、controller/README.txt、weapon/README.txt、dev/README.txt 同步更新。

当前 Prototype 参数：
- attack_range = 500。
- fire_interval = 0.5 秒。
- turn_speed_degrees = 180°/秒。
- fire_angle_tolerance_degrees = 6°。

结构原则：
- 自动瞄准和自动开火属于 WeaponRuntime，不属于 PlayerShipController。
- RuntimeShip 只负责创建 WeaponRuntime、提供目标组配置并转发 weapon_fired。
- 默认 player RuntimeShip 搜索 enemy_targets；未来敌方飞船可在 setup 前配置其他目标组。
- 同一艘飞船不同武器可独立选择不同目标。
- firepower 继续来自 WeaponModuleDefinition / Excel 数据链。
- 当前新增的射程、射击间隔、炮塔转速、瞄准容差仍属于运行时 Prototype 参数，尚未修改 Excel → JSON → .tres 数据结构。
- ShipData.grid_position / rotation_quarters 不因炮塔运行时瞄准而改变。
- 模块仍允许分开放置，不要求相邻、连通或填满网格。

当前范围：
- 已完成自动选敌、炮塔转向、瞄准判定、自动 fired 事件。
- 尚未加入 Projectile。
- 尚未加入真正敌我阵营系统；当前使用目标组区分。
- 尚未加入命中、伤害、模块生命值或模块失效。

- 收紧六类模块的类型专属参数。
- 最终确定：
  - 能量模块：energy_output
  - 动力模块：thrust
  - 武器模块：firepower
  - 防护模块：protection
  - 功能模块：暂无额外参数
  - 核心模块：暂无额外参数
- 删除功能模块中的 special_function。
- 删除功能模块中的 special_value。
- 同步调整 radar.tres 与相关显示逻辑。


========================================
v0.6
========================================

- 将模块定义由单一 Resource 进一步拆分为六种类型 Resource。
- 建立：
  - EnergyModuleDefinition
  - PropulsionModuleDefinition
  - WeaponModuleDefinition
  - DefenseModuleDefinition
  - FunctionModuleDefinition
  - CoreModuleDefinition
- 各类型 Resource 只显示对应的专属字段。
- 保持 ModuleDatabase 和飞船编辑器兼容。


========================================
v0.5
========================================

- 将模块参数从代码硬编码改为 .tres Resource 数据。
- 建立统一模块基础数据结构。
- 新增六个测试模块 .tres：
  - 小型反应堆
  - 主引擎
  - 机炮
  - 装甲
  - 雷达
  - 舰桥
- 新增 ModuleDatabase.tres。
- 飞船编辑器改为从 ModuleDatabase 读取模块。
- 左侧模块按钮改为根据数据库自动生成。
- 为后续数据驱动扩展打下基础。


========================================
v0.4
========================================

- 修复右侧飞船属性面板格式化参数不匹配导致的数据显示异常。
- 新增“设计状态”显示。
- 设计状态可提示：
  - 可出航
  - 缺少核心模块
  - 能量不足等不可出航原因
- 编辑阶段继续允许暂时能量不足。


========================================
v0.3
========================================

- 移除“模块之间必须相邻或连通”的限制。
- 模块可以在编辑网格中自由分开放置。
- 删除模块时不再进行舰体连通性检查。
- 保留模块不能重叠规则。
- 保留核心模块与能源合法性相关规则。


========================================
v0.2
========================================

- 调整能源规则。
- 修复除能量模块外其他模块难以正常放置的问题。
- 将能源限制拆分为：
  - 编辑阶段：允许暂时能量不足。
  - 最终设计合法性检查：总耗能不得高于总供能。
- 允许玩家先完成舰船布局，再补充能量模块。

v0.1
========================================

- 建立首个 Godot 4 飞船编辑器 Prototype。
- 建立网格吸附放置系统。
- 支持左键放置模块。
- 支持右键删除模块。
- 支持 R 键旋转模块。

- 支持模块重叠检测。
- 建立六种模块类型：
  - 能量模块
  - 动力模块
  - 武器模块
  - 防护模块
  - 功能模块
  - 核心模块
- 建立基础飞船属性统计：
  - 质量
  - 能量
  - 动力
  - 火力
  - 防护
- 核心模块作为未来“核心被击毁 → 飞船沉没”的判定入口。
