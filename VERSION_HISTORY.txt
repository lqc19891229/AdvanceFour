《前进四 / ADVANCE FOUR》版本更新记录

用途：
记录项目各版本的主要新增、调整与修复内容。

文档定位：
- README.txt：项目大方针、玩法定位与核心设计。
- WORKFLOW.txt：项目开发与协作的大方针。
- PROJECT_STRUCTURE.txt：项目框架与目录结构总纲。
- VERSION_HISTORY.txt：各版本实际更新内容记录。

记录原则：
1. 每次正式生成新版本时，在本文件顶部追加一条版本记录。
2. 只记录实际已经完成的修改，不记录尚未实现的计划。
3. 重点记录：新增功能、数据结构变化、目录调整、重要规则变化、Bug 修复。
4. 纯数值微调可合并描述，不必逐项记录。
5. 版本号与项目发布版本保持一致。


========================================
v0.13
========================================

新增：
- RuntimeShip 新增运行时朝向。
- 新增基础转向输入。
- 新增基于自身朝向的推进。
- 新增 get_heading_degrees()，用于读取当前舰首朝向。

调整：
- RuntimeShip 控制接口由二维世界坐标移动意图改为 set_control_input(throttle, turn)。
- throttle > 0 时沿舰首方向推进。
- throttle < 0 时沿舰尾方向倒车，当前倒车推力为前进推力的 50%。
- turn < 0 左转，turn > 0 右转。
- 0° 舰首方向统一定义为屏幕上方 Vector2.UP。
- ship_movement_test 操作调整为：
  - W / ↑：前进
  - S / ↓：倒车
  - A / ←：左转
  - D / →：右转
- 测试 HUD 新增当前朝向显示。
- PROJECT_STRUCTURE.txt 更新到 V0.13。
- game/ship/runtime/README.txt、game/ship/dev/README.txt 同步更新。

结构原则：
- RuntimeShip 仍只持有 ShipData，不复制模块结构。
- 飞船模块仍允许分开放置，不要求相邻、连通或填满网格。
- 当前转向速度属于 Prototype 基础参数，尚未由转向模块、质量分布或惯性计算。
- 本阶段仍未加入武器、伤害、模块失效、PlayerController 或 AIController。


========================================
v0.12
========================================

新增：
- 新增 game/ship/runtime/ 目录。
- 新增 ship_runtime.tscn，作为飞船进入实际游戏世界后的运行时场景。
- 新增 ship_runtime.gd，第一版负责：
  - 持有 ShipData
  - 按 ShipData 的网格位置绘制模块
  - 保存当前速度
  - 接收移动输入
  - 根据质量、推力与推重比计算基础移动
- RuntimeShip 提供 setup(ship_data)、set_move_input(direction)、get_speed() 基础接口。

调整：
- ship_movement_test 不再自己维护飞船绘制和移动实现。
- ship_movement_test 现在只负责：
  - 从 user://ships/test_ship.json 加载 ShipData
  - 实例化 RuntimeShip
  - 将 ShipData 传入 RuntimeShip
  - 读取 WASD / 方向键测试输入并传给 RuntimeShip
  - 显示测试数据
- RuntimeShip 不直接读取 JSON，也不硬编码玩家按键，为后续玩家控制器与 AI 共用同一飞船实体预留接口。
- PROJECT_STRUCTURE.txt 更新到 V0.12。
- game/ship/README.txt、game/ship/runtime/README.txt、game/ship/dev/README.txt 同步更新。

结构原则：
- ShipData 继续作为飞船结构与属性的唯一数据模型。
- RuntimeShip 不复制 ShipData.modules，不维护第二套模块结构。
- RuntimeShip 按 ShipData 中的实际网格位置显示模块，不自动压缩、连接或补齐空格。
- 飞船模块仍允许分开放置，不要求相邻、连通或填满网格。

当前范围：
- RuntimeShip 第一版仅完成基础平移与模块绘制。
- 暂未加入旋转、武器、伤害、模块失效、玩家控制器或 AI 控制器。


========================================
v0.11
========================================

新增：
- 新增根目录 WORKFLOW.txt。
- 新增 ShipSerializer，支持 ShipData 与 JSON 存档之间的序列化 / 反序列化。
- 飞船存档仅记录 module_id、网格位置与旋转，不保存 Resource 路径或运行时 uid。
- 飞船编辑器新增“保存设计”“加载设计”功能。
- 当前 Prototype 固定使用 user://ships/test_ship.json 作为测试存档。
- 新增 game/ship/dev/ 飞船系统开发测试目录。
- 新增 game/ship/dev/ship_movement_test.tscn 与 ship_movement_test.gd。
- 移动测试场景可读取已保存的飞船，并使用质量、推力、推重比验证基础移动效果。
- 移动测试支持 WASD / 方向键控制。

调整：
- 正式整理项目开发工作流。
- 明确 Excel → JSON → .tres → 游戏读取的数据工作流。
- 明确“设计确认 → 数据定义 → 最小实现 → 测试 → 集成 → 文档同步 → 打版本”的功能开发流程。
- 明确场景、脚本、Resource、数据 ID 命名规范。
- 明确 README 文档维护规则。
- 明确 Bug 修复与版本发布检查流程。
- PROJECT_STRUCTURE.txt 更新到 V0.11，并纳入 ShipSerializer 与飞船 dev 测试目录。
- 将原根级 res://dev/ 迁移到 res://game/ship/dev/，使测试代码按功能归属组织。
- WORKFLOW.txt 明确开发测试默认放在所属功能目录的 dev/ 下。
- game/ship/README.txt、game/ship/data/README.txt、game/ship/editor/README.txt、game/ship/dev/README.txt 同步更新。

规则：
- 飞船模块允许分开放置。
- 模块不要求相邻。
- 模块不要求彼此连通。
- 网格不要求全部填满，允许保留任意空格。
- 模块实际占用格仍然不能互相重叠。
- 当前 Prototype 仍限制每艘飞船最多安装 1 个核心模块。
- 编辑阶段仍允许临时能量不足；最终设计合法性要求总耗能 ≤ 总供能。

修复 / 健壮性：
- ShipSerializer 加载时会检查存档版本。
- 加载时会检查未知 module_id、非法 JSON、非法模块记录等情况。
- 加载恢复模块时继续复用 ShipData.can_place()，不会额外引入相邻、连通或填满规则。
