目录文档规则：
- 每个主要功能目录都放 README.txt。
- README.txt 说明目录职责、内部文件/场景/脚本功能与基本用法。
- 新增或删除重要文件时，同步更新所在目录 README.txt。

数据原则：
1. Excel 是策划数据唯一真源。
2. 六类模块分别维护在六个 Sheet，不重复填写 module_type。
3. Python 根据 Sheet 名确定 module_type，并负责校验和生成 JSON cache。
4. addons 仅作为 Godot 插件入口，不承载数据源或解析逻辑。
5. tools/data_import 集中管理 Excel、Python、JSON cache 和导入逻辑。
6. data/generated 只保存最终运行时 .tres，不手动修改。
7. 游戏系统通过 ModuleDatabase / DataManager 访问模块数据。
8. 飞船设计存档只记录稳定 module_id、位置和旋转；运行时通过 ModuleDatabase 恢复定义。
9. 飞船模块允许分开放置，不要求相邻、连通或填满所有格子；只禁止占用格重叠。
10. 开发测试按功能归属放置；飞船相关测试统一放在 game/ship/dev/。
11. ShipData 负责飞船结构数据；ShipRuntime 负责该数据进入游戏世界后的运行表现，不重复维护另一套模块结构。
12. RuntimeShip 的移动以自身朝向为基础：推进沿舰首方向，转向改变运行时 rotation；当前转向参数仍属于 Prototype 基础参数。
13. RuntimeShip 的局部原点与旋转中心统一使用核心模块（舰桥核心）的几何中心；只调整运行时显示偏移，不修改 ShipData 中的模块网格坐标。

14. 飞船控制来源与运行实体分离：PlayerShipController 只提供控制输入，RuntimeShip 负责执行运动；两者统一在物理帧更新，后续 AIController 可复用同一控制接口。
15. 武器静态数据继续由 ShipData / WeaponModuleDefinition 提供；RuntimeShip 为每个武器模块创建 WeaponRuntime，WeaponRuntime 只负责运行时发射事件，不复制静态模块数据。
16. 武器运行时采用可旋转炮塔：rotation_quarters 只定义初始朝向，战斗中 WeaponRuntime 可独立转向目标。
17. WeaponRuntime 默认在 RuntimeShip.weapon_target_group 指定的组中搜索攻击范围内最近目标，并在瞄准完成、冷却结束后自动开火；玩家控制器不负责武器瞄准或开火。
18. 当前 attack_range / fire_interval / turn_speed_degrees / fire_angle_tolerance_degrees 仍是 WeaponRuntime Prototype 参数，尚未纳入 Excel 数据真源。
19. WeaponRuntime fired 后由 RuntimeShip 创建 ProjectileRuntime；Projectile 作为 RuntimeShip 同级节点进入世界，独立直线飞行并按生命周期自动销毁。
20. ProjectileRuntime 使用 Area2D 基础碰撞；首次有效碰撞时发出 hit(target, firepower) 并销毁，RuntimeShip 通过 projectile_hit 向上转发。
21. Projectile 保存 source_owner，并忽略发射者自身及其子节点；当前只做基础自伤过滤，尚未建立正式阵营系统。
22. DamageReceiver 独立负责 max_hp / current_hp、damaged 与 destroyed；ProjectileRuntime 不直接维护目标生命值。
23. 当前 v0.20 由战斗层 / 测试层决定如何把 projectile_hit.firepower 交给 DamageReceiver；开发测试暂时直接使用 firepower 作为伤害值。
24. RuntimeShip 会为每个 ShipModuleInstance 创建独立 ShipModuleRuntime；其碰撞体严格按该模块实际网格位置与旋转后尺寸生成，因此分离模块之间的空格保持不可碰撞。
25. ShipModuleRuntime 组合 DamageReceiver，并把 Projectile 命中直接映射到具体 ShipModuleInstance；RuntimeShip 通过 module_damaged / module_destroyed 向上转发。
26. 当前 v0.21 每个模块统一使用 prototype_module_hp = 20；该数值尚未进入 Excel / ModuleDefinition。
27. WeaponRuntime 对支持 get_aim_point() 的目标使用运行时瞄准点；RuntimeShip 返回距离炮塔最近的未 destroyed 模块中心，已摧毁模块不再作为瞄准点。
28. 武器模块 destroyed 后，RuntimeShip 通过 module uid 找到对应 WeaponRuntime 并 set_operational(false)，停止搜索、瞄准与开火。
29. RuntimeShip.get_effective_thrust() 只统计未 destroyed 的动力模块；get_effective_acceleration_score() 使用 effective_thrust / 总质量，因此动力模块摧毁会降低实际推进能力。
30. RuntimeShip 核心模块 destroyed 后视作整船战斗失败：进入 removed_from_battle，停止移动与全部武器，发出 destroyed，并 queue_free() 从战斗场景移除。
31. 核心击毁只结束当前 RuntimeShip 战斗实例，不改写 ShipData 或飞船设计存档；分离模块、空格与不连通结构规则保持不变。
32. ProjectileRuntime 首次有效命中支持 apply_damage() 的对象时，会直接调用 apply_damage(firepower)；RuntimeShip.projectile_hit 只保留为观察 / 调试事件。
33. Projectile 作为 RuntimeShip 同级独立节点，其伤害逻辑不依赖 source_owner 存活，因此发射者核心摧毁并 queue_free() 后，已发射弹丸仍可继续命中和造成伤害。
34. RuntimeShip.get_effective_energy_output() 只统计未 destroyed 的能源模块；get_effective_energy_cost() 只统计未 destroyed 模块的 energy_cost。
35. 当有效供能低于有效耗能时，RuntimeShip 进入能源不足状态：所有 WeaponRuntime powered=false，推进有效推力归零；飞船不会因此直接退出战斗。
36. WeaponRuntime 将 operational（结构是否存活）与 powered（是否有能源）分离，能源恢复不会复活已经 destroyed 的武器。
37. RuntimeShip 使用 module_powered_by_uid 记录每个存活模块的运行时供电状态；供能不足时按 核心 > 能源 > 动力 > 防护 > 功能 > 武器 的 Prototype 固定优先级逐个分配能源，同类型按 module.uid 升序稳定分配。
38. is_energy_sufficient() 只表示是否足以覆盖全部存活模块需求；即使为 false，仍可能有部分模块保持 powered=true。
39. get_powered_energy_cost() 返回当前实际已供电负载；动力只统计 powered 的存活动力模块，WeaponRuntime.powered 也按对应武器模块单独设置。
40. RuntimeShip 的武器计数语义明确拆分：get_weapon_count() = 总 WeaponRuntime；get_operational_weapon_count() = 未 destroyed 的武器；get_active_weapon_count() = 未 destroyed 且当前 powered 的可工作武器。
41. 当前 v0.25.1 尚未实现玩家自定义供电优先级、手动开关模块、防护减伤或正式伤害类型；ShipData 静态统计继续保持不变。
