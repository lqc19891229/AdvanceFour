《星舰构筑Roguelite》项目立项方案
版本：V0.1
文档用途：内部立项 / 原型开发 / 团队沟通
项目类型：俯视角生存射击 + Roguelite + 模块化飞船构筑
参考方向：《土豆兄弟（Brotato）》的短局生存节奏 + 模块化飞船拼装构筑
暂定项目名：《前进四》 / Advance Four

一、项目概述
====================

1. 项目一句话描述

玩家驾驶一艘由网格模块拼装而成的宇宙飞船，在持续刷新的敌群中生存并战斗；每波战斗结束后，玩家通过购买、替换、旋转和组合武器、动力、能源、防御、散热等模块，不断重新设计自己的飞船，最终形成独特Build并击败Boss。

2. 核心定位

本项目不是单纯将《土豆兄弟》的角色替换成宇宙飞船，而是希望将“飞船结构本身”作为核心构筑对象。

传统生存Roguelite主要围绕：
角色属性 + 武器 + 道具

本项目主要围绕：
舰体网格 + 模块布局 + 模块联动 + 战斗属性 + Roguelite随机成长

玩家每局最重要的决策不是“拿哪件装备”，而是：
“我的船应该怎么造？”

3. 核心体验关键词

- 拼船
- 构筑
- 爽快射击
- 模块联动
- 随机成长
- 高重玩性
- 结构破坏
- 短局体验
- 易上手、难精通


二、目标玩家
====================

1. 核心目标用户

- 喜欢《土豆兄弟》《吸血鬼幸存者》等生存Roguelite的玩家
- 喜欢Build构筑和数值组合的玩家
- 喜欢机械、宇宙飞船、模块拼装题材的玩家
- 喜欢《背包乱斗》《FTL》《Cosmoteer》等布局和组合玩法的玩家
- 喜欢尝试不同流派并反复开局的玩家

2. 玩家核心需求

- 每一局都能明显形成不同Build
- 能够通过自己的布局获得收益，而不仅是数值叠加
- 武器组合有明显反馈
- 飞船成长过程视觉上足够直观
- 战斗节奏快，不因复杂系统导致操作负担过高
- 一局时间控制在20~30分钟左右


三、项目核心卖点
====================

1. 自由拼装飞船

玩家拥有一个网格化舰体，例如：

- 5×5 小型舰
- 7×7 中型舰
- 9×9 大型舰
- 特殊异形舰体

不同模块占用不同大小和形状的格子。

示例：

轻型激光炮：1×1
重型激光炮：1×2
轨道炮：1×3
反应堆：2×2
无人机机库：2×3
巨型主炮：3×3

玩家需要考虑空间利用率，而不是无限堆叠装备。

2. 模块位置决定Build

模块之间存在相邻、方向、距离和连接关系。

例如：

弹药箱：
相邻实体武器射速 +20%

冷却模块：
相邻模块产热 -30%

火控电脑：
同列武器暴击率 +15%

能源节点：
周围模块能耗 -20%

因此同样的装备，由不同玩家进行布局，最终性能也不同。

3. 能源与热量系统

飞船中的武器、护盾和推进器都会消耗能源。

反应堆负责提供能源。

武器和反应堆会产生热量。

散热模块负责降低热量。

能源和热量共同构成构筑限制。

玩家需要在以下内容之间进行取舍：

- 火力
- 生存
- 移动
- 散热
- 供能
- 空间

4. 模块真实受损

战斗中飞船模块可以被敌人攻击并暂时损坏。

例如：

右侧推进器被摧毁：
转向能力下降。

武器模块被摧毁：
对应武器停止工作。

连接结构被击毁：
部分模块可能暂时离线。

为了降低挫败感，普通模式下战斗结束后模块自动维修。

核心模块被摧毁则本局失败。

5. 简单操作 + 深度构筑

战斗操作保持简单。

建议方案：

WASD移动
鼠标控制朝向或自动瞄准
武器自动攻击

玩家主要精力集中在战斗间隙的造船和构筑，而不是高强度手操。

五、战斗系统
====================

1. 战斗视角

推荐使用2D俯视角。

优点：

- 开发成本低
- 信息表达清晰
- 飞船模块容易展示
- 大量敌人性能压力相对可控
- 适合自动射击玩法

2. 玩家控制

基础操作：

WASD：移动
鼠标：控制舰首朝向
Space：主动技能（可选）
ESC：暂停

武器默认自动射击。

部分特殊武器可以拥有：

- 自动锁敌
- 朝舰首射击
- 侧舷射击
- 360°射击
- 最近目标优先
- 最强敌人优先

3. 敌人设计

敌人主要分为：

普通敌人
高速敌人
远程敌人
护盾敌人
重甲敌人
自爆敌人
分裂敌人
召唤敌人
Elite
Boss

敌人的主要目的不是做复杂AI，而是不断对玩家当前Build提出压力。

例如：

大量小怪 → 测试AOE
重甲单位 → 测试单体DPS
高速怪 → 测试追踪与转向
远程怪 → 测试机动性
Boss → 综合测试Build

八、能源系统
====================

每个模块可能拥有：

- 能源消耗
- 能源生产
- 启动功率
- 持续功率

简化方案建议：

只使用一个“总能源”数值。

例如：

反应堆：
能源 +10

激光炮：
能源 -3

护盾：
能源 -4

推进器：
能源 -2

如果总需求超过总供给：

模块进入低效状态。

例如：

总供能：10
总耗能：12

则所有能源模块效率下降。

或者按照模块优先级进行断电。

原型阶段推荐第一种方案，逻辑更简单。

====================

1. 热量来源

散热器

3. 过热效果

建议分阶段：

0~60%
正常

60~80%
轻微性能下降

80~100%

100%以上
模块进入过热状态

4. Roguelite玩法延伸

可设计高风险流派。

例如遗物：

红线协议
温度超过80%时：
武器伤害 +50%

熔毁核心
每10%过热：
暴击率 +5%
受到伤害 +5%

这样玩家可以主动选择过热Build。


十、模块联动系统
====================

模块之间可以产生三类联动。

1. 相邻联动

弹药箱：
相邻实体武器射速提升。

冷却装置：
相邻模块热量降低。

2. 方向联动

火控电脑：
正前方一列武器暴击率提高。

能量导管：
横向连接的能量武器效率提升。

3. 数量联动

每拥有3个激光武器：
激光伤害 +10%

每拥有2个推进器：
移动速度 +5%

相邻规则是本项目区别于普通装备系统的重要机制。

二十一、主要风险
====================

1. 系统过于复杂

最大风险：

能源
热量
方向
动力
连接
模块破坏
弹药
重量
物流

如果全部加入，游戏可能从轻量Roguelite变成硬核飞船模拟器。

解决方案：

首版只保留：

空间
能源
热量
相邻
模块破坏

2. 拼船时间过长

如果玩家每波都花5分钟整理模块，会破坏战斗节奏。

解决方案：

- 模块自动吸附
- 一键替换
- 清晰相邻提示
- 快速旋转
- 支持锁定模块
- 商店阶段限制在合理时长内

3. Build最优解

如果最终所有玩家都使用相同布局，重玩性会下降。

解决方案：

- 不同舰体限制
- 随机模块
- 不同模块尺寸
- 遗物改变规则
- 多种武器体系

4. 模块破坏过于挫败

解决方案：

默认战斗结束自动维修。

高难度模式再考虑永久损伤。


二十二、项目差异化总结
====================

相比传统生存Roguelite：

普通游戏：
角色 + 武器 + 属性

本项目：
舰体 + 空间 + 模块 + 布局 + 资源 + 武器

核心差异是：

“Build不仅存在于数值面板，而是真正存在于玩家眼前的飞船结构中。”

玩家每一局都会造出一艘不同的船。

这是最重要的视觉记忆点和传播点。


二十三、Steam页面核心宣传语方向
====================

方向1：

造一艘船，然后活下来。

方向2：

每一个格子，都是你的Build。

方向3：

把武器、反应堆、推进器和装甲塞进有限的飞船空间里，
然后看看它能不能撑过下一波。

方向4：

这不是选择武器的Roguelite。
这是造武器平台的Roguelite。


二十四、项目立项判断
====================

建议立项方向：

“小体量、强系统、低美术成本、高重玩性”的独立游戏。

第一阶段不追求内容量。

首先验证三个问题：

1. 拼飞船本身是否有乐趣？
2. 布局变化是否能够明显影响战斗？
3. 玩家是否愿意为了新模块不断重新设计飞船？

如果这三个问题得到正向验证，则项目具有继续扩展的价值。

最重要的Prototype目标不是“做出一款完整游戏”，而是让测试玩家在获得一个新模块时产生：

“这个东西我要怎么塞进我的船里？”

以及：

“如果我这样摆，会不会更强？”

只要这两个问题能够持续出现，本项目的核心循环基本成立。
