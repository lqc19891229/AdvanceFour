《前进四 / ADVANCE FOUR》开发工作流

========================================
总原则
========================================

设计先确认
→ 数据先定义
→ 最小功能实现
→ 独立测试
→ 集成验证
→ 文档同步
→ 打版本

四个核心目录职责：

tools = 内容生产输入与工具
data  = Runtime 正式数据、配置、素材与数据定义
game  = 游戏逻辑、Runtime、Controller、Renderer、场景
core  = 跨系统基础设施

========================================
数据生产链
========================================

策划数值：
tools/data_source/game_data.xlsx
→ tools/import/import_excel.py
→ tools/cache/modules.json
→ Godot Data Importer
→ data/modules/<type>/*.tres
→ data/modules/module_database.tres

美术素材：
tools/art_source/
→ 制作 / 处理 / 导入
→ data/assets/
→ .tres / Scene / Runtime 引用

规则：
1. tools 中保存源数据与源素材。
2. data 中保存 Runtime 正式版本。
3. game 不直接引用 tools。
4. data 不按“generated/manual”分目录，只按内容类型分类。
5. 自动生成文件可以直接位于 data/modules 等业务目录，但必须在对应 README 中标注来源和禁止手工修改范围。
6. tools/art_source 使用 .gdignore，避免 Godot 将源素材重复导入。

========================================
功能开发工作流
========================================

每个新系统按：
1. definitions / 配置数据
2. Gameplay 逻辑
3. Runtime 表现
4. UI
5. 独立测试
6. 集成验证

纯数据结构放 data/definitions。
具体配置实例放 data 对应业务目录。
运行逻辑和场景放 game。
真正跨场景、跨系统的基础设施才进入 core。

========================================
场景与脚本管理
========================================

一个脚本一个主要职责。
Prototype 阶段允许适度合并，避免过度拆分。

命名：
- 场景：snake_case.tscn
- 脚本：snake_case.gd
- Resource 类：PascalCase
- 数据 ID：lower_snake_case

========================================
README 文档规则
========================================

主要目录包含 README.txt，说明：
- 职责
- 主要文件
- 使用方式
- 依赖
- 哪些内容自动生成 / 禁止手改
- 当前边界

目录职责、重要文件或使用方式变化时必须同步 README。

========================================
测试
========================================

系统开发测试跟随玩法系统放在 game/<system>/dev/。
统一验证入口：
python3 tools/verify_project.py --godot /path/to/godot

========================================
核心句
========================================

tools 生产内容，data 描述内容，game 执行内容，core 支撑整个项目。
