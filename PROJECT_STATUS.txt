《前进四》开发状态 v0.32.0

当前阶段：模块化飞船战斗 Prototype，已建立第一版连续战斗 / 战后整备闭环，尚未形成完整 Roguelike 游戏。

v0.32.0 完成战后闭环第一版：新增 RunState 与 BattleResult，正式战斗从 Run 战前快照生成玩家飞船；胜利确认结算后保留 Hull 战损并发放 Credits，Retry 恢复本场战前快照，失败不提交战损或奖励。新增 Battle Result Screen、全部维修、Run 整备模式与 stage_002；编辑器在整备模式只修改 RunState.current_ship，不覆盖永久设计。自动验证新增 Run regression。

v0.31.18 完成 human_basic Hull 正式美术第一版：16 张邻接 Tile 已替换为统一金属舰体风格，外露边使用装甲包边与高光，连接边保持无缝延伸，中心使用统一结构面板；Godot 4.6.1 导入与 Ship/Combat 回归通过。

v0.31.17 收口素材管理：删除 tools/art_source 与重复 PNG，模块贴图和 Hull Tile 只在 data/assets 保留唯一一份正式资源；tools 仅保留策划源数据、缓存、导入和验证工具。

v0.31.16 完成 Appearance Hull Tile 第一版：新增 HullAppearanceDefinition、human_basic.tres 与 16 个四方向邻接 Hull Tile；ShipAppearanceRenderer 由程序外壳升级为 mask→Texture2D 拼接，并保留缺图时的程序绘制 fallback。第一版仍不把外观 ID 写入 ShipData / ShipSerializer，Equipment 显示规则与战斗逻辑不变。

v0.31.15 完成项目目录职责重构：tools 负责源数据与生产工具；data 负责 Runtime 正式数据、Definition、配置实例与正式素材；game 只保留 Gameplay/Runtime/Scene；core 只保留跨系统基础设施。移除 data/generated 层级，自动生成模块资源直接归入 data/modules。模块 PNG 从 game 移至 data/assets。v0.31.17 进一步取消 tools 下的重复素材副本，素材统一由 data/assets 单份管理。

已完成：
- 飞船数据已拆为 Hull Layout + Equipment 两层；网格编辑器可独立铺设基础船体格并在其上安装/移动/旋转设备。
- Excel → Python → JSON cache → Godot 插件 → .tres 继续负责 Equipment 定义；Equipment 已取消 mass，共通 hp 也已移除，只有 Defense 保留 hp。Hull Cell 独立保存位置、max_hp/current_hp、质量与 hull_type。
- 玩家移动与转向、核心中心原点、独立炮塔自动选敌与射击。
- 模块贴图已纳入正式数据链：Excel 各模块 Sheet 使用 texture_path，Weapon 额外使用 turret_texture_path；导入后写入 JSON cache、模块 .tres 与 ModuleDatabase，不再由代码按 module_id 固定拼接路径。
- 首批模块 PNG 已提交并完成数据挂载；武器视觉拆为底座 + 炮塔。v0.31.11 新增独立 Appearance Layer；v0.31.16 已将 Hull 外壳从程序绘制升级为 16 邻接 Tile 拼接，Core / Weapon / Propulsion 外露，Energy / Defense / Function 被船壳包覆；编辑器仍完整显示 Hull + Equipment。
- 弹丸 swept ray 改为命中独立 Hull Cell 碰撞体；每个 Hull Cell 独立承伤并支持 HP-overkill 穿透。
- 武器火力、攻击范围、射击间隔、炮塔转速、弹速、射界和开火角容差已进入 Excel → JSON → .tres 数据链；不同武器可使用独立数值。weapon_cannon 当前射界为 180°。
- 攻击范围同时用于自动选敌和弹丸最大飞行距离；弹丸记录开火时射程与弹速，走完后消失，最后一帧不越界命中。
- 除 Defense 外 Equipment 不再拥有 hp；区域最大 HP = ShipHullCell.max_hp + 覆盖该区域的 Defense.hp。多格 Defense 的 hp 平均分配到覆盖区域。Equipment 效率仍取覆盖 Hull Cell 健康度平均值，核心覆盖 Hull 全毁时整船移除。
- 敌舰 AI：选择最近有效玩家目标、转向追踪、接近与倒车保持距离。
- 编辑器 → 单敌舰交火测试 → 返回编辑器并恢复设计。
- 飞船移动已改为纯推力模型：最高速度、加速度与松油减速度只由当前有效引擎推力乘对应 scale 决定；Hull / Equipment 质量不参与移动计算。
- 当前移动参数为 speed_scale = 2.5、acceleration_scale = 1.0、deceleration_scale = 1.5、reverse_thrust_ratio = 0.5；动力所在 Hull 受损或断电会同步降低有效推力，从而降低最高速度和加减速能力。
- 飞船编辑器属性顶部显示预计最高速度，随模块布局变化更新，并提示供能不足。
- 飞船编辑器支持 Hull/Equipment 分层操作：Hull 格独立放置/拆除；Equipment 只能完整安装在 Hull 上，并支持选中、移动、旋转，保留实例 uid。
- 战斗世界固定星点 / 网格参照，HUD 显示实时速度与坐标，明确前进 / 倒车 / 转向操作。
- 战斗支持有限波次、逐个生成敌舰、HUD、胜负结算、重开 / 返回；v0.32.0 起正式 Run 可在胜利后进入战果页，携带战损进入维修 / 整备 / 下一战。
- v0.31.13 将 battle.tscn 正式化为所有关卡共用的战斗容器；新增 BattleDefinition Resource 与 definitions/stage_001.tres。飞船编辑器只负责验证/保存设计并选择关卡配置，不再承载战斗规则。后续普通关卡、精英战与 Boss 战均应复用 battle.tscn，通过 BattleDefinition 数据化差异。
- v0.31.14 完成敌舰与波次内容数据化：新增 EnemyShipDefinition、BattleWaveDefinition、scout / gunship 蓝图；stage_001 现在直接定义三波敌舰组合。Battle 不再固定调用 build_starter_design() 生成敌舰。显式关卡路径加载失败会进入 ERROR，Retry 保持当前 BattleDefinition，并纳入自动回归。
- 最终清场后等待空中弹丸结束；核心 Equipment 所覆盖 Hull 全部损毁时判定失败，失败优先于同帧胜利。

当前入口：
1. F5 运行默认飞船编辑器，完成合法设计，点击“出航战斗”创建 Run。
2. 清除 stage_001 后点击“结算并继续”，战损写入 RunState 并获得 100 Credits；战果页可全部维修、进入整备或直接进入 stage_002。stage_002 奖励 150 Credits。R 重开当前战斗并恢复本场战前快照；Esc 放弃当前 Run 并返回设计器。
3. 可 F6 单独运行 game/combat/battle.tscn；默认使用 data/battles/stage_001.tres，无存档时使用调试示例船。
4. “敌舰 AI 测试”和旧 ship_movement_test.tscn 保留为独立诊断入口。

- 正式战斗已使用 EnemyShipDefinition 敌舰蓝图；当前仅有 scout / gunship 两个 Prototype 蓝图，数值强度与更多敌舰类型仍需后续设计。旧 AI 测试仍是独立诊断入口。
- AI 距离与转向参数仍为 Prototype 参数；武器射程 / 射速 / 转速 / 弹速 / 开火角容差已进入 Excel。
- 武器正式射界已实现：安装方向定义射界中心，选敌 / 炮塔旋转 / 开火均受 firing_arc_degrees 约束；引擎喷射空间与全项目阵营数据尚未实现，本场碰撞层已避免己方误伤。
- 永久存档仍只保存设计模板；RunState 独立保存当前一轮的飞船状态。胜利提交战损，失败不提交；Retry 使用本场战前快照。
- Hull Layout 当前仍允许不相邻、不连通与任意空格；Equipment 必须完整覆盖在现有 Hull Cell 上。

- 第一版 Hull Cell 固定使用 basic_hull：max_hp = 20、mass = 2；Hull 的 mass 暂保留为结构数据，但当前不参与速度或加速度计算。
- ModuleDefinition 已移除 mass 与共通 hp；只有 DefenseModuleDefinition 保留 hp。Excel 源表也已删除所有 mass 列以及非 Defense 的 hp 列。
