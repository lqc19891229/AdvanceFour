《前进四》开发状态 v0.45.0

当前阶段：模块化飞船战斗 Prototype，已建立第一版连续战斗 / 战后整备闭环，尚未形成完整 Roguelike 游戏。

v0.45.0 合并战利品与胜利结算，移除成长奖励三选一；战损改为按真实船体/模块布局绘制的交互快照，支持选格查看效率、局部/全部维修、缩放和拖动。只有未处理战利品阻止继续，维修可跳过。

v0.44.2 补齐武器图标回退与可重建工具；战利品、商店、仓库、空间站优先使用专用图标，武器无专用图标时优先显示炮塔。新增组合图标实际解码与各界面取图回归。

v0.44.0 完成维修改装空间站第一版：原 REFIT 路线节点升级为空间站入口，进入后免费将当前飞船全部 Hull 修复至满血；空间站读取 StationDefinition 配方，用零件制造模块，制造结果进入仓库并受容量限制；零件不足或仓库不足时原子失败。空间站仍可进入 Run Refit 编辑器进行改装。

v0.43.0 完成双资源经济系统：移除当前玩法层的 Credits，正式加入能量结晶与零件。能量结晶是宇宙通用交易通货，仅用于商店购买；零件是工程资源，当前用于战后 Hull 维修，1 缺失 Hull HP = 1 零件。BattleDefinition / BattleResult 支持两种资源奖励；stage_001 为 100 能量结晶 + 12 零件，elite_001 为 220 + 30，stage_002 为 150 + 20。空间站制造模块留待 v0.44。

v0.42.0 完成第一版精英战：新增 elite_001 战斗配置包，不新增精英专用运行时代码。精英战仍使用普通 BATTLE 节点和共享 battle.tscn，通过 battle.tres 的更强波次/220 Credits 与 loot.tres 的 4 件不重复高收益掉落表现风险收益差异；Prototype Route 第一战后现有商店、整备、精英战三条分支，最终汇合到第二战。

v0.41.1 整理战斗数据目录：data/battles 改为按 battle_id 建立配置包，每个目录包含 battle.tres 与 loot.tres。Battle 与 Loot 仍是独立 Resource，但物理上归档在一起；普通战、精英战与 Boss 后续均通过这两份数据表达差异，不新增专用战斗代码。

v0.41.0 完成数据驱动随机掉落表：新增 LootTableDefinition / LootTableEntry；BattleDefinition 可引用掉落表，按权重抽取指定数量模块并支持是否重复与数量范围。当前不包含装备稀有度、随机词条或实例品质。

v0.40.0 完成战利品临时区第一版：固定模块奖励不再在胜利提交时自动进入仓库；胜利后进入独立 Loot Screen，玩家逐件选择带走或放弃。带走统一经过仓储容量检查，全部处理完才能继续战果结算和路线。

v0.39.0 完成仓库管理场景：新增 game/run/warehouse，可从 Route Map 随时查看当前模块仓库；支持 Used / Capacity、超载提示、按模块类型筛选、同 ID 堆叠、模块详情与路线合法的“前往整备”。Function Sheet 正式加入 storage_capacity，标准货舱进入 game_data.xlsx，并新增独立 function_cargo_hold.png 贴图，不再使用内建数据/雷达占位图。

v0.38.0 完成模块仓库第一版：Run 默认拥有 12 点基础模块仓储；库存模块按 definition.size.x × size.y 占用容量，Hull 不计入模块仓储。新增 2×2 标准货舱（+16 仓储，未安装时自身占用 4）；商店购买、战斗固定模块奖励、成长模块奖励均受仓储容量约束，容量不足时原子失败。整备界面与商店显示仓储占用。

v0.37.1 完成商店节点四槽化：ShopDefinition 固定 4 个商品槽，按 combat / systems / utility / any 槽规则从商品池无重复生成；生成结果与 SOLD 状态保存在 RunState，刷新或重新进入不会换货；购买后不补货，商品继续直接进入 Run Inventory。商店 UI 改为四张商品卡。

v0.37.0 完成星系路线节点第一版：正式 Run 改为数据化 Prototype 星系航线；第一战后在星图中二选一进入补给商店或整备站，再汇合至第二战并到达航线终点。新增路线 Resource、节点可视化、RunState 节点推进与分支合法性检查。

v0.36.0 完成商店第一版：新增数据化 ShopDefinition / ShopItemDefinition 与独立补给商店场景；stage_001 战果领取成长奖励后可进入商店，用 Credits 购买模块/Hull 并直接写入 Run Inventory。余额不足时原子失败；最终关不显示商店。

v0.35.0 完成战后奖励选择第一版：新增 BattleRewardOption 与 reward_choices 数据；stage_001 在固定 100 Credits 外提供轻型装甲×1 / 机炮×1 / Hull×2 三选一。未领取成长奖励前可维修但不能进入整备或下一战，领取后只将选中项加入 Run Inventory。

v0.34.0 完成 Run Inventory 第一版：当前 Run 新增模块库存与 Hull 库存；战斗支持固定模块/Hull 奖励；Run 整备安装会消耗库存、拆除返还库存、移动/旋转免费，并禁止一键清空绕过规则。stage_001 奖励轻型装甲×1 + Hull×1，stage_002 奖励机炮×1。

v0.33.0 完成局部维修与战后整备第一版：RunState 支持单格 Hull 维修；战果页列出受损 Hull、覆盖 Equipment、当前与修复后模块效率，并允许玩家用 Credits 只修关键区域。维修仍保持 1 缺失 Hull HP = 1 Credit，资金不足时原子失败；Equipment 继续不拥有独立 HP。

v0.32.1 修正 Run 末端流程与文档结构：stage_002 胜利后的战果页新增“结束 Run 并返回设计器”，避免当前最终关卡出现无可用下一步；Victory 提交增加重复结算保护；PROJECT_STRUCTURE 目录树修正。

v0.32.0 完成战后闭环第一版：新增 RunState 与 BattleResult，正式战斗从 Run 战前快照生成玩家飞船；胜利确认结算后保留 Hull 战损并发放 Credits，Retry 恢复本场战前快照，失败不提交战损或奖励。新增 Battle Result Screen、全部维修、Run 整备模式与 stage_002；编辑器在整备模式只修改 RunState.current_ship，不覆盖永久设计。自动验证新增 Run regression。

v0.31.18 完成 human_basic Hull 正式美术第一版：16 张邻接 Tile 已替换为统一金属舰体风格，外露边使用装甲包边与高光，连接边保持无缝延伸，中心使用统一结构面板；Godot 4.6.1 导入与 Ship/Combat 回归通过。

v0.31.17 收口素材管理：删除 tools/art_source 与重复 PNG，模块贴图和 Hull Tile 只在 data/assets 保留唯一一份正式资源；tools 仅保留策划源数据、缓存、导入和验证工具。

v0.31.16 完成 Appearance Hull Tile 第一版：新增 HullAppearanceDefinition、human_basic.tres 与 16 个四方向邻接 Hull Tile；ShipAppearanceRenderer 由程序外壳升级为 mask→Texture2D 拼接，并保留缺图时的程序绘制 fallback。第一版仍不把外观 ID 写入 ShipData / ShipSerializer，Equipment 显示规则与战斗逻辑不变。

v0.31.15 完成项目目录职责重构：tools 负责源数据与生产工具；data 负责 Runtime 正式数据、Definition、配置实例与正式素材；game 只保留 Gameplay/Runtime/Scene；core 只保留跨系统基础设施。移除 data/generated 层级，自动生成模块资源直接归入 data/modules。模块 PNG 从 game 移至 data/assets。v0.31.17 进一步取消 tools 下的重复素材副本，素材统一由 data/assets 单份管理。

当前入口：
1. F5 运行默认飞船编辑器，完成合法设计，点击“出航战斗”创建 Run。
2. 清除 stage_001 后点击“结算并继续”，战损写入 RunState 并获得 100 能量结晶 + 12 零件；在统一结算页处理战利品并按需维修后返回星图，在补给商店 / 空间站 / 精英战中选择分支，再进入 stage_002。stage_002 胜利后返回星图并选择航线终点结束 Run。R 重开当前战斗并恢复本场战前快照；Esc 放弃当前 Run 并返回设计器。
3. 可 F6 单独运行 game/combat/battle.tscn；默认使用 data/battles/stage_001/battle.tres，无存档时使用调试示例船。
4. “敌舰 AI 测试”和旧 ship_movement_test.tscn 保留为独立诊断入口。
