《前进四》当前开发状态（2026-10-09）
工程：Godot 4.6.1。当前为模块化舰船战斗与固定测试路线 Prototype，并非完整 Roguelike 成品。

【实际默认入口】
project.godot → res://game/run/route/route_map_screen.tscn。
初次进入星图时，优先从 user://ships/test_ship.json 读取合法的玩家设计；否则使用 Battle.build_starter_design() 的内置示例。然后 RunState.start_run_with_test_route() 建立 fixed_test_sector 固定测试路线。RouteMapGenerator.generate() 已实现，但未接入默认入口。

【当前实现】
- 飞船数据：ShipData = Hull Cell + Equipment；ShipSerializer v3 JSON 支持旧格式迁移。
- 玩家/敌舰共用 ShipRuntime：每格 Hull 独立承伤、模块效率受损、供能优先级、推进和独立炮塔。敌舰由 game/enemy/enemy_controller.gd 控制，玩家由 PlayerShipController 控制。
- 敌舰配置：data/enemies/scout.tres、gunship.tres 保存身份和 AI 距离；data/ships/templates/enemy_scout.json、enemy_gunship.json 保存船体/设备布局；EnemyShipFactory 经 ShipSerializer 加载，不再使用旧 EnemyRuntime。
- 编辑器：game/ship/editor 为玩家设计/Run 整备入口；game/ship/template_editor/ship_template_editor.tscn 为开发环境 F6 独立模板编辑器，复用 ShipGridView。模板存 data/ships/templates，和 user://ships/test_ship.json 分离。
- 模板安全：覆盖与删除需要确认，新建/加载时未保存内容提示；覆盖前尝试保存 .json.bak（本地备份，已忽略 Git）。
- 战斗：共享 battle.tscn + BattleDefinition/BattleWaveDefinition；胜利自动生成结算并提交结果，进入统一战果、战利品与可选维修页面；失败清空 Run 后进入 Game Over。
- Run：能量结晶用于交易，零件用于维修/制造；仓库、商店、空间站、酒馆及星图节点有各自场景。测试星图为固定路线；随机路线生成器是非默认功能。
- 正式模块由 Excel → tools/cache → Godot 导入插件 → data/modules/*.tres 数据链生成。

【尚未完成/边界】
- 开局模板选择未接入星图默认入口；玩家设计仍优先取 user://ships/test_ship.json。
- 默认测试路线不代表计划中的完整动态 Roguelike 关卡推进。
- 模板编辑器用于 Godot 开发环境，不提供发布游戏中的项目文件写入。
